# Codocu v0.2 — Plan Outline

> Status: outline approved 2026-05-22. Actionable items, not yet a step-by-step
> implementation plan. Supersedes the prose v0.2 section in `docs/todo.md`.

**What v0.2 is:** Codocu stops owning spec→plan→code and becomes a **doc-first
quality keeper** that delegates planning and coding to specialist skills.
Underneath that, the doc methodology gets re-founded on a clearer core.
**Methodology first**, then architecture; the build pipeline is deferred.

**Cross-cutting decision:** The design docs (`principles`, `voice`,
`doc-standard`) are the **single source of truth** and are written as clean,
self-contained **injectable units**. v0.2 skills are **hand-written as faithful
projections** of those docs — debuggable directly, and serving as the
**calibration exemplar** for the deferred `/build` pipeline.

**The core, restated:** Code is a first-class spec — it precisely describes how
the product works *right now* (the complete spec). Auxiliary docs (everything
outside code) carry what code can't: why it's built this way, where it's headed,
the changes planned as deltas, the cross-file picture. An aux doc never re-states
what the code already spells out. Every methodology rule grows from this core;
the Neph distance/backlink rule is *one* such rule, not the core itself.

## Track A — Methodology (do first)

> **Status (2026-05-22):** A1, A2, A3, A5 landed (owner-revised). A4 resolved by
> descoping — elevation pass, METADOCU, and ADR-detail rehomed to todo/templates.
> B7 (voice) parked pending the learning-skill work. See
> `docs/plans/2026-05-22-track-a-methodology.md`.

- **A1.** Rewrite `principles.md` — three plain-English core beliefs: *Clarity
  is the point*, *Code is the spec; aux docs are the complement*, *Tool-agnostic*.
  Persona moves out to `voice.md`; flow framing dropped. Written as an injectable
  unit.
- **A2.** Define **"auxiliary docs"** as a first-class term — everything outside
  code; carries why / direction / deltas / the cross-file picture; never rewords
  the code.
- **A3.** Rewrite `doc-standard.md` as the rules that grow from the core: doc
  tied to what it describes (placement + backlinks); summaries survive
  meaning-preserving refactors (a rename doesn't break them); prefer business
  words over code words; say only what code can't (negative space); the narrow
  Neph distance+backlink rule for naming foreign symbols.
- **A4.** Resolve the Neph open edges — ADRs *may* name code (justified by
  co-change + backlink); business summaries *may* refuse code names. Fold the
  mechanics (tiers, breadcrumb, METADOCU) into the runtime reference the skill
  loads, not the design specs.
- **A5.** Docstrings as first-class — make the refactor-resistance rule concrete:
  what a good code summary names vs. avoids.

- **B-extract** (foundational) — distill the Neph corpus into the four assets.
- **B-core** — the one flexible base `/codocu` skill; orient-only-when-needed;
  two modes (subtractive for bad docs, generative for fresh repos); delegates;
  removes `propose`/`doc-code`/`apply`. (Old B1/B2/B3.)
- **B-review** — strict Sonnet-viable reviewer subagents; rules = the smell
  checklist; includes `fold`/`sync` and the rehomed elevation pass. (Old B4.)
- **B-integrate** — `codocu.md` via `CLAUDE.md`; post-implementation
  verification; specialist-skill composition; mechanical `#METADOCU`/leakage
  guard. (Old B5.)
- **B-cleanup** — README rewrite, `codocu.md`, archive `flows.md` + sync-flow
  doc, finish `voice.md`, decide `init`; skeletal fresh-repo templates. (Old
  B6/B7.)
